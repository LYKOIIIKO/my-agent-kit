# Domain docs

Read `GLOSSARY-MAP.md` at the repository root to find the glossary for each relevant case. Each case keeps its `GLOSSARY.md` in its own folder. Use its terms when writing about that case.

When a case gets its first glossary, add a relative link under `Cases` in the map.

Read relevant architecture decision records (ADRs) in the root `docs/adr/` and in the case's `docs/adr/`, if present. If a proposal conflicts with an existing ADR, identify the conflict.
